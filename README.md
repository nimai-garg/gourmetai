# Gourmet Chef

Personalized recipe inspiration and USDA food search, built by [Nimai Garg](https://www.linkedin.com/in/nimaigarg).

**[Live website](https://gourmetchef.app)** · React · Firebase · OpenAI · Netlify

## What it does

- Email/password and Google sign-in with private Firebase profiles.
- Saved dietary preferences, allergy restrictions, and cooking experience.
- Meal-specific questions for cuisine, flavor, cooking time, and servings.
- AI recipe generation with ingredients, steps, and estimated nutrition.
- USDA FoodData Central search with pagination and nutrient units.
- Responsive landing page, account settings, and password reset.

Recipe suggestions are generated by AI and may be inaccurate. Users should check ingredients against their allergies; nutrition estimates are not verified food measurements.

## Architecture

```text
React / Vite → Firebase Authentication + Firestore profiles
             → Netlify recipe function → Firebase token verification → OpenAI
             → USDA FoodData Central
```

The browser sends a Firebase ID token with each recipe request. The function verifies the token before contacting OpenAI. The OpenAI key stays on the server. Only explicitly listed public Firebase/USDA values are included by the build.

The repository targets the web app. Unused Expo/React Native scaffolding, experimental views, and the unused Mailchimp server have been removed; historical versions remain in Git.

## Run locally

Requires Node.js **22.12 or newer**.

```sh
npm ci
cp .env.example .env
# Fill in the existing Firebase web app configuration and server-side OpenAI key.
npm run start:api
# In a second terminal:
npm start
```

Open http://localhost:3000. Vite proxies `/.netlify/functions/*` to the local API on port 5001. Restart both processes after changing `.env`.

`REACT_APP_FIREBASE_*` names are retained for compatibility with the existing Netlify project. They are public web app identifiers, not admin credentials. **Never prefix a private key with `REACT_APP_` or `VITE_`.** `OPENAI_MODEL` defaults to `gpt-4o` and is configurable on the server. USDA uses a quota-limited `DEMO_KEY` unless `REACT_APP_USDA_API_KEY` is supplied.

## Checks

```sh
npm run check
npm audit
```

`check` runs the React regression tests, API tests, and production build. Provider calls in automated tests are mocked; these checks do not prove live credentials or billing are configured. GitHub Actions runs these checks for pushes and pull requests, plus a production dependency audit.

For a local production preview, keep the local API running and use `npm run build` followed by `npm run preview` (http://localhost:4173).

## Deploy to the existing Netlify project

`netlify.toml` builds with `npm run build`, publishes `build/`, packages `netlify/functions/chat.js`, and handles browser routes. Do not deploy only the static folder: recipe generation also needs the function.

1. Set the `REACT_APP_FIREBASE_*` variables in the **build** environment.
2. Set `OPENAI_API_KEY` and `FIREBASE_API_KEY` (or `REACT_APP_FIREBASE_API_KEY`) in the **Functions** environment. Both Firebase keys must belong to the same project.
3. Enable Email/Password and Google sign-in in Firebase. Include `gourmetchef.app`, `www.gourmetchef.app`, and localhost in authorized domains.
4. Publish Firestore rules with `firebase deploy --only firestore:rules --project gourmetai-c3818` when changing those rules.
5. Deploy from the linked Git branch, or use an authenticated Netlify CLI with `netlify deploy --build --prod` from this repository. A manual deploy can publish reviewed changes before a Git commit.
6. Verify sign-in, preference persistence, a real recipe, nutrition search, and refreshes on nested URLs on the domain.

The function limits input to 12,000 characters, limits output to 1,800 tokens, rejects truncated recipes, and uses provider timeouts. Its Netlify configuration requests 10 calls per IP/domain per minute. Confirm that the rate-limit rule appears in the deployment log; it is not enforced by the local Express proxy. Set provider budget limits separately.

## Public repository security

`.env` files, deployment state, and Python caches are ignored. Do not commit service-account credentials or private keys. OpenAI and Mailchimp keys were present in older revisions: the owner must revoke any exposed credentials that are still active. Removing a key from the current tree does not remove it from Git history. History has not been rewritten.
